# 交接说明（给队友 / 给未来的自己）

更新：2026-11-19　分支：`feat/net`　基线：`main@41290d3`（北航扩展版）

## 1. 一分钟看懂

在 2026 北航扩展版 xv6（VFS + HAL，xv6fs/ext2/fat32，RISC-V + LoongArch）上加了：

- **网络**：virtio-net 驱动（RISC-V 走 mmio，LoongArch 走 pci）、ARP/IPv4/ICMP/UDP/TCP、socket 系统调用（socket/bind/sendto/recvfrom/connect/listen/accept）、内核环回。
- **动态链接**：`mmap` 系统调用、`exec` 的 `PT_INTERP` 与 auxv、用户态 `ld.so`（DT_NEEDED 加载 .so、RELATIVE 重定位、JUMP_SLOT 符号解析）。

## 2. 环境

Ubuntu 24.04/26 均可（本机在 WSL 里验证）：

```sh
sudo apt install -y gcc-riscv64-linux-gnu gcc-14-loongarch64-linux-gnu \
                    qemu-system-misc dosfstools mtools bc
# 若无 loongarch64-linux-gnu-gcc 软链：
sudo ln -sf /usr/bin/loongarch64-linux-gnu-gcc-14 /usr/local/bin/loongarch64-linux-gnu-gcc
```

## 3. 构建 / 运行 / 测试

```sh
./scripts/build.sh riscv          # 编译内核与 fs.img
./scripts/run.sh riscv            # 启动（Ctrl-A x 退出）
./scripts/build.sh loongarch
./scripts/run.sh loongarch
./scripts/test-usertests.sh riscv # 回归，输出 PASS/FAIL
```

启动后可直接输入：

| 命令 | 验证 |
| --- | --- |
| `dltest` | 用户态加载 libmath.so 并调用 add/mul/fib |
| `dynhello` | PT_INTERP + ld.so 动态链接 |
| `udptest` | UDP 环回收发 |
| `tcptest` | TCP 握手 + 双向收发 |

开机自检：ARP 请求 → 网关应答 → ping（打印 RTT）。

## 5. 已知缺口与下一步（按优先级）

1. **LoongArch 的 `dynhello`**：已定位到"第二次 `read()` 不返回"。
   - `exec` 识别 `PT_INTERP`、把 `/ld.so` 映射到 `0x30000000`、跳解释器都正常（实测 `ld.so: start argc=1`、`entry=0x10198`）。
   - `ld.so` 打开主程序并读入 37480 字节成功（`open dynhello -> 3`、`read n=37480`）。
   - 随后打开 `libmath.so` 成功（`open libmath.so -> 3`），但读取它的 `read()` 永远不返回；同一镜像里 `dltest` 读同一个文件正常。
   - 已排除：`ld.so` 的 BSS 映射不足（第二个 LOAD 的 `memsz=0x50080` 覆盖到 `0x30052068`，缓冲区在范围内）。
   - 下一步建议：把 `read` 的目标缓冲从 `ld.so` 的 BSS 换成 `mmap` 出来的匿名页再试；若仍挂，抓 `virtio_disk` 的请求/完成计数，确认是不是盘 I/O 的唤醒丢失。
   - **新增对照（重要）**：写了 `src/user/readtest.c`，按 `dynhello` → `libmath.so` 的顺序连续 open/read，两个文件都读完（37480 / 18168 字节），完全正常。所以不是"第二次读"、不是文件、不是读取顺序的问题，而是 **`ld.so` 作为解释器进程的上下文**特有（它的代码/数据在 `0x30000000` 段）。下一步应重点查：`copyout` 写入解释器段时的 `walkaddr`/PTE_U 处理，以及解释器进程的 `p->sz` 与独立映射区的关系。

   附：直接 `exec ld.so` 在 RISC-V 上同样失败（它没有 auxv），这是预期的，不是 LA 特有问题。
2. **TCP 是停等发送**：一次一段、等 ACK，功能正确但吞吐低。要做滑动窗口：发送队列 + 累积 ACK + 快速重传。
3. **测例接口未确认**：iperf/netperf/libctest/libcbench 没拿到，`select`/`getsockopt` 等是否需要补未知。
4. **文档与视频**：设计文档第 5/6/8/9/10 节、PPT（有 15 页大纲）、演示视频（10–30 分钟）都还没做，合计占 40%。
