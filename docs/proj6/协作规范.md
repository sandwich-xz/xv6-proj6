# 协作规范

## 1. 仓库与远端

| 远端 | 地址 | 用途 |
| --- | --- | --- |
| `upstream` | `gitlab.eduxiji.net/.../project3136859-388873.git` | 赛事基线，**只读，不 push** |
| `origin` | 我们的 GitHub 仓库 | 日常协作 |

初始化（每人一次）：

```sh
git clone <我们的仓库地址> xv6-proj6
cd xv6-proj6
git remote add upstream https://gitlab.eduxiji.net/T2026100069911110/project3136859-388873.git
git remote set-url --push upstream no_push   # 防手滑
```

## 2. 分支

| 分支 | 用途 | 谁能合 |
| --- | --- | --- |
| `main` | 可运行、可演示的状态 | 队长 |
| `feat/net-<点>` | 协议栈/驱动 | A/B |
| `feat/dl-<点>` | 动态链接 | C |
| `docs/<点>` | 文档 | 全员 |
| `fix/<点>` | 修 bug | 全员 |

规则：

- 从最新 `main` 切分支，分支名短、说明白在做什么。
- 一个分支只做一件事；超过 400 行改动就拆。
- 合并前 rebase 到 `main`，不要留 merge 提交噪音。

## 3. 提交

格式：`模块: 做了什么`，一句话说清结果。

```
net: 修 LoongArch virtio-net 头长度（PCI 12 字节）
dl: ld.so 支持多库 DT_NEEDED 顺序加载
docs: 补测试数据表
```

- 一次提交一个逻辑改动，别把"修 bug + 改格式"混在一起。
- 改了内核代码，提交信息里写清**验证方式**（跑了哪个自测/回归）。
- 不提交二进制、不提交 `fs.img`、不提交 `.so`。

## 4. 合并（PR）

1. 推分支 → 开 PR，标题同提交格式。
2. PR 描述写：改了什么、怎么验证、有没有已知限制。
3. 至少 1 人 review；reviewer 重点看：是否动到别人的文件、是否破坏回归。
4. CI 没有，所以**合并前本地跑** `scripts/test-usertests.sh riscv`，把 PASS 截图/日志贴到 PR。

## 6. 节奏

- 每周日 21:00 复盘 20 分钟：本周完成 / 卡点 / 下周计划，产出 `docs/proj6/weekly/Wn.md`。
- 距截止 12/27 还有 5 周，前 3 周冲功能，后 2 周只留文档、视频、提交。
- 卡住超过 4 小时就在群里说，别自己耗一天。

## 7. 质量红线

- `usertests -q` 必须全过才能合并到 `main`。
- 新增功能至少配一个用户态自测（参考 `udptest.c`/`tcptest.c`/`dltest.c`）。
- 内核里不许留 `printf` 调试输出（除非设计成常驻日志，如 `arp:`/`ping:`）。
- 双平台改动必须两边都构建通过再合并。
